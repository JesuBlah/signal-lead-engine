# Signal Lead Engine

Finds Finnish companies that are actively running Google Ads but have gaps in
their tracking/site quality (no conversion tracking, no Meta Pixel, weak
website) — then presents them as a searchable, filterable lead dashboard with
a built-in contact-email finder.

It's two parts that work together:

1. **The pipeline** (`scripts/*.py`) — scans domains, verifies who's really
   advertising on Google, scores/segments them, and writes an AI-style
   analysis per company.
2. **The dashboard** (`web/`) — a Next.js app that reads the pipeline's
   output and gives you a UI to browse, filter, and find emails for those
   leads. This is what you deploy and hand to your client.

---

## How the pieces fit together

```
scripts/scan.py        →  resultsd/results.jsonl, results.csv
        │                 (raw scan: does each domain have Google Ads tags,
        │                  conversion tracking, Meta Pixel, quality issues?)
        ▼
scripts/report.py      →  resultsd/HOTLIST.csv, resultsd/SUMMARY.md
        │                 (ranks + segments leads into A / B / C)
        ▼
scripts/verify.py      →  resultsd/HOTLIST-verified.csv
        │                 (confirms via Google's public Ads Transparency
        │                  Center that each domain is a LIVE advertiser —
        │                  not just "has the tracking pixel installed")
        ▼
scripts/analysis.py    →  analyses/{domain}.md
        │                 (one short Finnish-language findings +
        │                  recommendations write-up per company)
        ▼
web/scripts/sync-data.ts  →  web/data/HOTLIST-verified.csv, web/analyses/*.md
        │                 (copies the latest pipeline output into the app)
        ▼
   npm run dev / deploy  →  the dashboard you actually look at
```

`data/live-advertisers-verified.csv` is a saved snapshot of an earlier run
(164 verified live advertisers) — sample/reference data, not regenerated by
the scripts above.

## Part 1 — The pipeline (`scripts/`)

Pure Python 3 standard library — no `pip install` needed.

| Script | What it does |
|---|---|
| `scan.py` | Given a CSV or list of domains, fetches each site and detects Google Ads tags, conversion tracking, Meta Pixel, and basic quality issues (slow response, no H1, stale copyright year, etc). Resumable — writes incrementally to `results.jsonl` so an interrupted run doesn't lose progress. |
| `report.py` | Reads `results.jsonl`, ranks leads by score, segments them into **A** (running ads, weak site), **B** (running ads, no conversion tracking), **C** (running ads, solid site), and writes `HOTLIST.csv` + a human-readable `SUMMARY.md`. Can optionally join revenue/employee data from a local `finderfirm` SQLite DB. |
| `verify.py` | The credibility check: confirms via Google's public Ads Transparency Center that a domain is a genuinely **live** advertiser (ran ads within ~12 months), not just a site that happens to have the Google Ads tag installed. Appends `google_verified_live`, `google_advertiser_name`, `ads_status` and writes `HOTLIST-verified.csv`. |
| `analysis.py` | Turns each verified row into a short Finnish-language analysis markdown file (`analyses/{domain}.md`) — findings + 2–3 recommendations, used to make outreach feel personalized. |

### Re-running the pipeline

```bash
cd signal-lead-engine
python3 scripts/scan.py --input your-domains.csv --output resultsd
python3 scripts/report.py --results-root resultsd
python3 scripts/verify.py --hotlist resultsd/HOTLIST.csv
python3 scripts/analysis.py --hotlist resultsd/HOTLIST-verified.csv --out analyses
```

Then push the fresh results into the dashboard (see `sync-data` below).

## Part 2 — The dashboard (`web/`)

Next.js 16 (App Router) + TypeScript + Tailwind.

### Run it locally

```bash
cd web
npm install
npm run dev
```

Open **http://localhost:3000**.

Note: `npm run dev` only starts a dev server. If you instead want a
production run (`npm run start`), you must build first:

```bash
npm run build
npm run start
```

### What's on the dashboard

- **Home (`/`)** — search by company/domain/city, filter by niche, by
  segment (A/B/C), and by whether Google Ads / conversion tracking / Meta
  Pixel were detected. Summary stat cards up top.
- **Company page (`/company/[domain]`)** — status pills for each signal,
  quality-issue flags, the full rendered AI analysis for that company,
  company info (city, employees, platform, advertiser name), and a contact
  finder.
- **Contact finder** — the CSV's `email` column is usually empty, so each
  company page has a "Find email" button that scrapes that company's
  homepage + common contact-page paths (`/yhteystiedot`, `/contact`,
  `/about`, etc.) for a public `mailto:`/email address and phone number.
  Results are cached in `web/data/emails.json`.
- **Dark mode** — toggle in the navbar, remembered per-browser. First paint
  respects the OS/browser dark-mode preference with pure CSS (no flash);
  an explicit toggle choice always overrides that.

### Keeping the dashboard's data fresh

The dashboard reads its own copies at `web/data/HOTLIST-verified.csv` and
`web/analyses/*.md` — it does **not** read `resultsd/` or the top-level
`analyses/` directly (this keeps the deployed app self-contained). After
re-running the pipeline, sync the new output in:

```bash
cd web
npm run sync-data
```

### Bulk-finding emails from the command line

Instead of clicking "Find email" one company at a time:

```bash
npm run find-emails                    # every domain still missing an email
npm run find-emails -- --verified      # only Google-verified live advertisers
npm run find-emails -- --limit 20      # cap how many to scan
npm run find-emails -- --domain foo.fi # just one domain
npm run find-emails -- --force         # re-scan even if already cached
```

Writes incrementally to `web/data/emails.json`, so an interrupted run loses
nothing. This only finds *publicly listed* emails — it never guesses or
fabricates addresses. Spot-check before outreach.

## Deploying it (so your client in Finland — or anyone — can actually open it)

`localhost:3000` only works on your own machine. Your phone's Network URL
(`http://192.168.x.x:3000`) only works on the same Wi-Fi. Neither reaches
Finland or works when your laptop is closed. For a real public URL:

1. **Push to GitHub**
   ```bash
   cd web
   git init
   git add .
   git commit -m "Signal Lead Engine dashboard"
   git remote add origin https://github.com/YOUR-USERNAME/signal-lead-engine.git
   git branch -M main
   git push -u origin main
   ```

2. **Deploy on [Vercel](https://vercel.com)** (free tier is enough)
   - Sign up with GitHub → "Add New Project" → import the repo
   - It auto-detects Next.js — click **Deploy**
   - You get a live URL (e.g. `signal-lead-engine.vercel.app`) reachable
     from any device, anywhere, 24/7, with no laptop required

3. **Important limitation on serverless hosting:** the "Find email" button
   still works live on Vercel, but the `emails.json` cache doesn't persist
   between requests there (serverless functions get a fresh disk each
   time). Workaround: run `npm run find-emails` locally, then commit +
   push the updated `web/data/emails.json` — Vercel auto-redeploys, and the
   cached results go live within a minute:
   ```bash
   npm run find-emails -- --verified
   git add data/emails.json
   git commit -m "Update scraped emails"
   git push
   ```
   If you want the on-demand button itself to persist permanently without
   this manual step, that requires swapping the JSON cache for a real
   database (e.g. Vercel KV or Postgres).

4. **Alternative: your own server/VPS**, if you'd rather not use Vercel.
   Build once, then keep it alive with a process manager:
   ```bash
   npm run build
   npm install -g pm2
   pm2 start npm --name "signal-lead-engine" -- run start
   pm2 save
   pm2 startup   # prints a command to enable auto-start on reboot — run it
   ```
   Put it behind nginx/Caddy for HTTPS and a real domain.

## Project structure

```
signal-lead-engine/
├── README.md              ← you are here
├── scripts/                ← Python pipeline (stdlib only)
│   ├── scan.py
│   ├── report.py
│   ├── verify.py
│   └── analysis.py
├── resultsd/                ← pipeline output
│   ├── results.jsonl / results.csv   (raw scan)
│   ├── HOTLIST.csv                   (ranked, pre-verification)
│   ├── HOTLIST-verified.csv          (final, Google-verified list)
│   └── SUMMARY.md                    (human-readable run summary)
├── analyses/                ← one {domain}.md write-up per company
├── data/                    ← sample/reference snapshot
│   ├── README.md
│   └── live-advertisers-verified.csv
└── web/                     ← the Next.js dashboard (deploy this folder)
    ├── src/app/               (dashboard + company pages + API route)
    ├── src/components/        (UI: cards, filters, badges, contact finder)
    ├── src/lib/                (CSV parsing, markdown loading, scraper)
    ├── scripts/find-emails.ts (bulk CLI scraper)
    ├── scripts/sync-data.ts   (pulls latest pipeline output into web/)
    ├── data/HOTLIST-verified.csv  (the app's working copy of the hotlist)
    ├── data/emails.json           (scraped-email cache)
    └── analyses/                  (the app's working copy of the write-ups)
```
